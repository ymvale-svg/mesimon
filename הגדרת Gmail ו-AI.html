הגדרת Gmail ועוזר ה-AI

כ-15 דקות · פעם אחת בלבד · מניח שהכניסה עם Google כבר מוגדרת
מה זה נותן: כל עובד מחבר את תיבת ה-Gmail שלו פעם אחת, ומשימון:
  • שולח ממנה את המיילים של משימות ה-AI — מהכתובת של העובד, ונשארים אצלו ב"דואר יוצא";
  • סורק כל בוקר את המיילים שלא נקראו ומציע מהם משימות — עם צ'קליסט, יעד ושיוך לעמיתים;
  • קולט מאותה תיבה את התשובות לבקשות ה-AI;
  • עוצר תזכורות כשהעובד כתב לנמען בעצמו — ושואל מה המצב.
הרשאה: אישור אחד ב-Google, לקריאה ולשליחה (gmail.readonly + gmail.send). משימון שולח רק מה שהעובד אישר, ותזכורות לפי המדיניות. הוא לא מוחק ולא מסמן כנקרא. אין שליחה מתיבת מערכת: מי שלא חיבר את התיבה — משימת AI במייל אינה זמינה לו.

1. מפתח ה-AI (Claude)

  1. נכנסים ל-console.anthropic.com ← API Keys ← Create Key.
  2. ב-Render: השירות ← Environment ← מוסיפים ANTHROPIC_API_KEY עם המפתח.
  3. מומלץ להוסיף גם TOKEN_ENCRYPTION_KEY — מחרוזת אקראית ארוכה כלשהי. בעזרתה מוצפנים אסימוני ה-Gmail במסד הנתונים. בלעדיה נוצר קובץ מפתח ליד מסד הנתונים.
אל תחליפו את TOKEN_ENCRYPTION_KEY אחרי שעובדים חיברו את התיבות — החיבורים הקיימים יפסיקו לעבוד, וכל אחד יצטרך לחבר מחדש.

2. הפעלת Gmail API ב-Google Cloud

באותו פרויקט שבו הוגדרה הכניסה עם Google:

  1. console.cloud.google.com ← APIs & Services ← Library ← מחפשים Gmail API ← Enable.
  2. APIs & Services ← OAuth consent screen:
    • User type: Internal. זה החשוב ביותר — רק משתמשי eshelltd.co.il יוכלו לאשר, ו-Google לא ידרוש אימות וביקורת אבטחה (שאחרת נמשכים שבועות).
    • Data access / Scopes ← Add or remove scopes ← מסמנים .../auth/gmail.readonly ו-.../auth/gmail.send ← Save.
  3. אין צורך בכתובת חזרה נוספת — החיבור משתמש באותה כתובת של הכניסה (/api/auth/google/callback).

4. מה כל עובד עושה

  1. "החשבון שלי" ← 📧 Gmail ועוזר ה-AI ← חיבור Gmail.
  2. מאשרים ב-Google — מסך אחד, לקריאה ולשליחה (לסמן את שתי התיבות אם מופיעות).
  3. חוזרים למשימון, בוחרים טווח לסריקה ראשונה — וההצעות מופיעות בדף הבית תחת ✨ ממתין לאישורך.
