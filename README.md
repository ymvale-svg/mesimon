# משימון

מערכת ניהול משימות ופרויקטים — **אשל הירדן · מחלקת שיווק ומכירות**
מימוש מלא של האפיון המפורט לפיתוח, גרסה 1.0.

---

## הפעלה

דרישה יחידה: **Node.js גרסה 22.5 ומעלה** ([nodejs.org](https://nodejs.org)).
אין צורך ב-`npm install` — למערכת אין שום תלות חיצונית.

לחיצה כפולה על:

```
הפעלת משימון.bat
```

או מהטרמינל:

```bash
node server/index.js
```

הדפדפן ייפתח בכתובת `http://localhost:3000`. השרת מדפיס גם כתובת רשת פנימית
(למשל `http://10.0.0.113:3000`) שדרכה עמיתים ברשת המשרדית יכולים להתחבר מהמחשב שלהם.

## התאמה לאפיון

### פרק 2 — משתמשים ורמות גישה
ארבע רמות: מנהל מערכת, מנהל מחלקה, עובד פנימי, ספק חיצוני. ההרשאה נקבעת ברמת המשתמש
ונאכפת בצד השרת בכל בקשה.

### פרק 3 — ארכיטקטורת בורדים
הבורד הפנימי ובורדי הספקים הם **ישויות נפרדות ברמת מבנה התצוגה**, לא רק ברמת הרשאה:

- לכל משימה שדה `board_id` המשויך לבורד ספציפי, בנוסף לשדה האחראי.
- לוח המשימות הפנימי שולף `board.type = 'internal'` בלבד — משימות ספקים אינן מופיעות בו כלל.
- כל ספק מקבל בורד ייעודי משלו, שנוצר אוטומטית עם יצירת הספק.
- הקצאת משימה לספק מעבירה אותה פיזית לבורד של אותו ספק.
- למנהלים יש תצוגת-על "כל משימות הספקים" המרכזת את כל בורדי הספקים — בנפרד מהבורד הפנימי.

### פרק 4 — ישויות נתונים
`users` · `vendors` · `boards` · `board_columns` · `projects` · `tasks` · `checklist_items` ·
`comments` · `comment_mentions` · `attachments` · `notifications` · `audit_log` · `settings` ·
`automation_rules` · `templates` · `saved_filters` · `sessions`

לוג הפעולות מוגן בטריגרים ברמת מסד הנתונים — כל ניסיון עדכון או מחיקה נדחה.

### פרק 5 — המסכים

| מסך | מימוש |
|---|---|
| **1. דף הבית האישי** | ארבעה ווידג׳טים עם ספירה ומעבר לרשימה מסוננת, פיד עדכונים, פעמון התראות, חיפוש גלובלי הכולל ארכיון, לוח שנה שבועי. הבחנה חזותית בין "דחוף" (עדיפות) לבין "באיחור" (חריגת זמן) — שתי תגיות נפרדות שיכולות להופיע יחד. |
| **2. לוח המשימות** | שלוש תצוגות: **טבלה מקובצת** (ברירת מחדל), כרטיסיות (קנבן) עם גרירה ושחרור, וציר זמן. סינון לפי פרויקט·אחראי·סטטוס·עדיפות·תאריך עם שמירת מסננים אישיים, פעולות אצווה, ארכיון נפרד. |
| **3. כרטיס משימה** | פאנל פרטים, תגובות עם תיוג `@שם`, גרירת קבצים עם שמירת כל הגרסאות (ללא דריסה), לוג היסטוריה בלתי ניתן לשינוי, אזהרה חזותית וחסימת סגירה כשקיימת תלות במשימה שטרם הושלמה. |
| **4. פורטל ספקים** | תצוגה ייעודית לכל ספק, רק המשימות שהוקצו לו, ללא גישה לנתוני צוות, פרויקטים או ספקים אחרים. הערות פנימיות ולוג הבקרה מוסתרים לחלוטין. העלאת תוצרים, הוספת הערות וסימון "הושלם". תמיכה בהרשאת "צפייה בלבד". |

#### תצוגת הטבלה המקובצת

מסך העבודה היומיומי. שורה אחת למשימה, בצפיפות מידע גבוהה בהרבה מקנבן:

- **קיבוץ מתקפל** לפי פרויקט (ברירת מחדל), אחראי, סטטוס, עדיפות או בורד. בתצוגת הספקים
  הקיבוץ הוא לפי בורד הספק. לכל קבוצה פס צבע בקצה הימני.
- **תא הסטטוס הוא הפקד** — מלבן צבעוני במלוא רוחב התא; לחיצה פותחת בחירה ומשנה מיד.
  אותו הדבר בעדיפות, באחראי ובתאריך היעד.
- **עריכת כותרת במקום** — לחיצה על הכותרת הופכת אותה לשדה טקסט. Enter שומר, Escape מבטל.
- **שורת סיכום לכל קבוצה** — פילוח סטטוסים כפס מוערם, אחוז השלמה, מספר החריגות ותאריך היעד האחרון.
- **שורת הוספה מהירה** — כתיבה ו-Enter יוצרים משימה בקבוצה, בלי דיאלוג. ערך השדה שלפיו קיבצנו
  נקבע אוטומטית (פרויקט, אחראי, עדיפות או סטטוס).

כל תא נערך רק אם השרת סימן את המשימה כניתנת לעריכה עבור המשתמש המחובר
(`canEdit` / `canChangeStatus` ב-`shapeTask`). האכיפה עצמה בשרת — התצוגה רק נגזרת ממנה.

### פרק 6 — מטריצת ההרשאות
מוגדרת פעם אחת ב-`server/permissions.js`, נאכפת בכל נקודת קצה, ומוצגת כטבלה במסך
**ניהול המערכת → מטריצת הרשאות**. הממשק בונה את עצמו ממנה — אין כפילות בין שרת ללקוח.

### פרק 7 — לוגיקה עסקית ואוטומציות

| סעיף | כלל | פרמטר |
|---|---|---|
| 7.1 | תזכורת ראשונה לספק, X ימים לפני היעד | `vendor_reminder_days_before` |
| 7.1 | התראה מקדימה למנהל, Y שעות לפני היעד | `manager_alert_hours_before` |
| 7.1 | התראה מיידית למנהל בחריגה בפועל | — |
| 7.2 | הקפצת משימה דחופה שסטטוסה לא השתנה | `escalation_hours_urgent` |
| 7.3 | יצירת המופע הבא של משימה חוזרת | `recurring_default_policy` |
| 7.4 | הפעלת משימה עתידית בהגיע תאריך ההפעלה | — |

**כל הפרמטרים המספריים הם הגדרות קונפיגורביליות** הניתנות לשינוי ממסך הניהול תוך כדי
עבודה — אף אחד מהם אינו מקודד בקוד.

**סעיף 7.5 — גמישות:** המנוע בנוי כרישום של טריגרים ופעולות. הוספת כלל חדש נעשית ממסך
הניהול על ידי חיבור טריגר לפעולה, ללא שינוי מבני. הוספת טריגר או פעולה מסוג חדש היא
הוספת ערך אחד לרישום ב-`rules-engine.js`.

### פרק 7.3 — מדיניות משימות חוזרות חופפות
ברירת המחדל: לא נוצר מופע כפול עד לסגירת הקודם. המדיניות ניתנת לשינוי גם ברמת המערכת
וגם ברמת המשימה הבודדת (`recurrence_policy`).

### פרק 8 — זרימת עבודה מול ספק חיצוני

```
1. הקצאה לספק        → ממתין להעלאת תוצרים   (מנהל)
2. העלאת תוצרים      → הועלה — ממתין לבדיקה   (ספק, מתקדם אוטומטית עם ההעלאה)
3. סימון הושלם       → ממתין לבדיקת הצוות     (ספק)
4. בדיקת הצוות       → בבדיקת הצוות           (מנהל)
5א. אישור סופי       → הושלם ואושר            (מנהל)
5ב. דחייה            → נדרש תיקון             (מנהל) ──┐
                                                       └→ חוזר לשלב 2
```

בדחייה נשלחת לספק התראה אוטומטית עם ההערות, והמשימה חוזרת לסטטוס פעיל בבורד שלו.
כל התקשורת מתועדת בתוך המערכת.

### פרק 10 — שלבי הפיתוח
כל ארבעת השלבים מומשו: בסיס המערכת · ספקים ואוטומציה · תבניות והרחבה (תבניות משימות
ופרויקטים, משימות חוזרות ועתידיות, עמודות מותאמות אישית) · דוחות ואנליטיקה (עומס, ביצועי
ספקים, התקדמות פרויקטים, ייצוא CSV).

## הערות טכניות לפני עלייה לייצור

המערכת מוכנה לעבודה ולבדיקות קבלה מול המחלקה. לפני שימוש תפעולי מלא מומלץ:

1. **סיסמאות** — משתמשי הדמו מגיעים עם סיסמה `1234`. יש להחליף לכל המשתמשים.
2. **HTTPS** — כרגע השרת עובד ב-HTTP בתוך הרשת הפנימית. לחשיפה מחוץ לרשת נדרש
   פרוקסי עם תעודה, ועוגיית הסשן צריכה לקבל `Secure`.
3. **גיבוי** — יש לגבות את `data/mesimon.db` ואת תיקיית `uploads/` בגיבוי היומי של השרת.
4. **הרצה כשירות** — כדי שהשרת יעלה אוטומטית לאחר אתחול, כדאי להגדיר אותו כ-Windows
   Service (למשל באמצעות NSSM) במקום הרצה ידנית מקובץ ה-BAT.
